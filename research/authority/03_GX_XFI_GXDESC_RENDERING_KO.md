# GX·XFI·gxdesc·렌더링 연구 정본

## GX에서 확인한 구조

- 노드 계층: 부모 인덱스, 플래그, 이름/경로 토큰
- 노드별 로컬 행렬과 프레임 데이터
- 메시: 정점, 삼각형 인덱스, UV, 노멀/색, 재질 슬롯
- 텍스처 참조와 재질 상태
- 장식 평면, 빌보드, 발광/알파 계열처럼 일반 불투명 메시와 다른 자산

현대 설치본의 GX 777개를 모두 파싱했고 1,554개 정적/애니메이션 검사 렌더를 만들었다. 파싱 성공은 강한 근거지만 원본 픽셀 동일성을 뜻하지 않는다.

## 경로와 문자열

- 원본 바이트 문자열은 CP949로 보존하고 표시용 UTF-8 문자열을 별도로 만든다.
- Windows 원본 호출과 같이 경로는 대소문자 무시로 해결한다.
- 한글 파일명은 “깨진 문자열을 다시 추측”하지 말고 원본 바이트→CP949 decode를 한 번만 수행한다.
- BMP 참조가 있을 때 같은 stem의 TGA가 실제 색상 텍스처일 수 있다.
- `A.bmp`/alpha companion은 별도 알파 재질 입력으로 취급한다.
- companion 토큰이 없다는 사실과 색 텍스처가 없다는 사실은 다르다.

## 확인된 픽셀/재질 규칙

- X1R5G5B5 계열 16비트 색 해석
- TGA/BMP 읽기와 same-stem 해결
- UV는 GX가 제공한 좌표를 보존하고 임의 재투영하지 않음
- 저장된 정점 노멀은 round-trip/export용 속성이다. 확인된 지형 XYZRHW+diffuse+UV 경로에서 엔진 조명으로 재곱하지 않는다.
- 평면/빌보드 자산은 실제 평면 노멀과 노드 플래그를 보고 분기한다.
- 0x1000/0x2000/0x7000 계열 방향 플래그가 있지만 모든 GX에 전역 적용하면 정상 모델이 망가진다.

아직 파일별 원본 픽셀 골든이 없는 재질 예외가 있으므로, ‘777/777 파싱’을 ‘777/777 완벽 렌더’라고 쓰지 않는다.

## GX 행렬 적용 원칙

- 자식 월드 행렬은 부모 월드 행렬과 자식 로컬 행렬의 계층 합성으로 만든다.
- 좌표계 변환은 parser 내부 원본 수치와 host(Blender/Godot) 변환을 분리한다.
- 축을 바꾸기 위해 정점 자체와 노드 행렬에 같은 보정을 이중 적용하지 않는다.
- AABB 중심은 뷰어 카메라 framing에만 쓸 수 있으며 조립 소켓이 아니다.
- 자리표시자처럼 작은 행렬을 무조건 버리는 전역 규칙은 금지한다. 자산군·플래그·호출자 근거가 있어야 한다.

## XFI에서 확인한 구조

- XFI는 GX와 무조건 같은 stem의 1:1 파일이 아니다.
- 하나의 XFI는 여러 action 구간과 여러 채널을 가질 수 있다.
- 구간은 `[start, end)`로 다룬다.
- 행렬, 정점, UV, 재질 채널이 같은 시간축에서 변할 수 있다.
- 어떤 GX는 XFI 없이 GX 내부 정적/프레임 정보만 사용한다.
- XFI가 있다는 사실은 ‘움직이는 로봇’이라는 뜻만은 아니며, 효과·재질·장면 변화에도 사용될 수 있다.

## XFI ID 의미의 올바른 취급

ID 0~8에 하나의 전역 행동명을 붙이는 표는 확정되지 않았다. 동일 숫자라도 호출자와 자산 용도에 따라 선택 의미가 달라질 수 있다. 올바른 키는 다음 조합이다.

`(호출자/모드, GX 자산군, XFI 파일, action ID, 구간, 재생 상태)`

따라서 임포터와 엔진에는 ID 숫자와 원시 구간을 그대로 노출하고, ‘대기/이동/공격’ 표시는 증거가 있는 profile에서만 별칭으로 제공한다.

## gxdesc.ini

확인된 핵심 역할:

- `[Files]` 계열 인덱스가 런타임 자산 테이블과 연결됨
- 런타임 693개 record가 gxdesc `[Files]`와 정확히 대응한 조사 결과가 있음
- 공격 descriptor가 GX/XFI/텍스처/폭발/음향 코드로 이어지는 자산 식별의 중심
- 파일명만으로 의미를 추측하는 대신 인덱스와 상위 호출 record를 함께 봐야 함
