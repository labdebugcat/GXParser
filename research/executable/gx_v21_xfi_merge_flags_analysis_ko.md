# GX v2.1 XFI·merge·노드 표시 플래그 분석

## merge 계층의 의미

- 전체 GX 780개 중 68개에서 `merge_head`, `merge_a`, `merge_b`가 발견됐다.
- 세 이름은 항상 한 세트로 나타나며 대부분 arm/무장 계열이다.
- `merge_head`, `merge_a`, `merge_b`의 노드 플래그는 일반적으로 `0x00210030`이다.
- 클라이언트의 `FUN_00459580`은 노드 플래그 `0x10`이 있으면 첫 자식 `node+0x5c`부터 형제 `node+0x64`를 전부 재귀 호출한다.
- 초기 호출 `FUN_00459580(root, 0, state)`은 override flags가 0이며, merge 노드들은 `0x10`을 갖기 때문에 a/b 가지를 모두 순회한다.
- 따라서 `merge_a/merge_b`는 둘 중 하나를 고르는 런타임 선택 분기가 아니라, 양쪽 무장 구성 요소를 묶은 계층 컨테이너이다.

## 노드 마지막 DWORD 확정·반영

- GX 노드 행렬 다음 4바이트는 런타임 노드 구조체 `+0x40`의 render flags로 로드된다.
- `flags & 0x10`: 자식 계층 순회.
- `flags & 0x20`: 해당 노드의 메시/재질 목록 제출.
- 기본 렌더 호출의 override는 0이므로 이 두 비트가 실제 기본 표시 여부를 결정한다.
- 설치 코퍼스에서 자식 또는 메시가 있지만 flags가 0인 특수 GX 7개/메시 8개가 확인됐다. v2.1은 이들을 원본 클라이언트처럼 기본 렌더에서 숨긴다.
- Blender에는 `gx_node_flags`, `gx_client_visible`을 보존하고, Native 뷰어도 같은 표시 판정을 사용한다.

## XFI 행렬 형식 수정

- GX 노드 행렬은 이동이 직렬화 인덱스 `3,7,11`에 있다.
- XFI 소켓 행렬은 Direct3D row-vector 형태를 유지하여 이동이 인덱스 `12,13,14`에 있다.
- 기존 구현은 XFI에도 GX 변환을 사용해 Blender의 마지막 행에 이동을 넣고 있었다. 이 경우 소켓 위치가 실제 부품 배치에 적용되지 않는다.
- v2.1은 `_matrix_from_xfi`/`_matrix_to_xfi`를 별도로 두고 XFI 경계에서 전치한다.
- XFI 소켓 Empty 가져오기, Unit Assembly의 body/arm/accessory 배치, XFI 내보내기 왕복 모두 새 변환을 사용한다.
- `body1.xfi`의 소켓 5개에 대해 원본 `m30/m31/m32`와 Blender translation이 일치하고 16개 float가 오차 `1e-6` 이하로 왕복됨을 Blender 5.2에서 검증했다.

## XFI 코퍼스 현황

- XFI 777개가 모두 현재 파서로 분류된다.
- 주요 소켓 수는 0, 1, 5, 6개이다.
- body 계열은 주로 5개, legs 계열은 주로 1개이며 일부 B 계열은 6개를 사용한다.
- 소켓 인덱스별 부품 범주의 최종 명칭은 실행 파일의 조립 호출 경로를 더 추적해야 하지만, 행렬 좌표계 자체는 이번 단계에서 수정·확정됐다.
