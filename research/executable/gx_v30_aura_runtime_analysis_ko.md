# Nova1492 GX 분석 v3.0 — 오라 런타임 복원

## 확정 결과

오라 상태 갱신 함수는 `FUN_00453F60`, 오라를 실제 GX 렌더 호출로 전달하는 함수는 `FUN_004541E0`이다.

설치본에서 `auratype`을 사용하는 6개 모델은 모두 `크기증가 색감소`이며, 클라이언트 플래그는 `0x0D000000`이다.

## 0x44바이트 gxdesc 레코드 교정

레코드 시작 주소는 `DAT_0076604C`다. 이전에 확인한 `DAT_00766064`는 레코드 시작이 아니라 +0x18의 `anispeed` 필드다.

| 오프셋 | 필드 |
|---:|---|
| +0x18 | anispeed |
| +0x1C | scale |
| +0x20 | tail/aura/auratype 플래그 |
| +0x24 | pair Files 인덱스 |
| +0x28 | aura 첫 색상 |
| +0x2C | aura 두 번째 색상 |
| +0x30 | aura 첫 배율 |
| +0x34 | aura 두 번째 배율 |
| +0x38 | aura 시간 진행 계수 |
| +0x3C | aura 정수 주기, 기본 1000 |
| +0x40 | aura material, 기본 1 |

## auratype 상태기계

`FUN_00453F60`은 정규화된 진행률과 두 배율·두 ARGB 색을 받아 현재 배율과 색을 계산한다.

| 마스크 | 토큰 | 동작 |
|---:|---|---|
| 0x01000000 | 크기증가 | 첫 배율에서 두 번째 배율로 선형 보간 |
| 0x02000000 | 크기진동 | sin 기반 배율 보간 |
| 0x03000000 | 크기감소 | 두 번째 배율에서 첫 배율로 선형 보간 |
| 0x04000000 | 색증가 | 첫 색에서 두 번째 색으로 선형 보간 |
| 0x08000000 | 색진동 | sin 기반 색 보간 |
| 0x0C000000 | 색감소 | 두 번째 색에서 첫 색으로 선형 보간 |
| 0x10000000 | 알파증가 | 알파 전진 보간 계열 |
| 0x20000000 | 알파진동 | 알파 sin 보간 계열 |
| 0x30000000 | 알파감소 | 알파 역방향 보간 계열 |

마지막 알파 그룹의 한국어 토큰명은 로더 비교 순서에 따른 명명이며, 현재 설치된 gxdesc에는 사용 사례가 없다. 비트 동작 자체는 같은 2비트 상태 그룹으로 확정된다.

## 런타임 흐름

1. GX 인스턴스의 +0x44에서 Files 슬롯 번호를 읽는다.
2. 레코드 +0x20의 aura 활성 비트 0x8을 확인한다.
3. 게임 시간과 레코드 +0x38/+0x3C로 반복 진행률을 계산한다.
4. `FUN_00453F60`이 현재 색과 배율을 계산한다.
5. 계산 결과를 `FUN_00457140`에 넘기고 일반 GX 렌더 호출 `FUN_0042C0A0`을 수행한다.

## v3.0 도구 반영 및 검증

- 모든 설치 aura 섹션이 `0x0D000000`으로 변환되는지 검사했다.
- Native 보고서에 aura type flags를 추가했다.
- Blender GX 메시 사용자 속성에 `gxdesc_auratype_flags`를 추가했다.
- Python 문법 검사와 설치본 기반 변환 검사를 통과했다.

동적광원 정의는 0x18바이트 구조로 GX 자원 객체의 +0x14에 복사되는 것까지 확인했다. 구체적인 광원 갱신·합성은 다음 단계에서 계속 추적한다.
