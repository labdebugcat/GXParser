# GX v2.0 노드 행렬·계층 분석

## 실행 파일에서 확정한 행렬 규칙

- 노드 렌더 함수 `FUN_00459580`은 진입 시 현재 전역 월드 행렬을 스택에 저장하고 `FUN_004589c0`을 호출한다.
- `FUN_004589c0`은 현재 행렬과 노드 구조체 시작 주소의 4×4 행렬을 `FUN_00435620`으로 곱한 뒤 그 결과를 현재 월드 행렬로 설정한다.
- `FUN_00435620`의 16개 float 연산을 직접 확인한 결과 일반적인 row-major `A × B` 행렬 곱이다.
- 이후 `node+0x5c`의 첫 자식부터 `child+0x64`의 다음 형제를 재귀 렌더하고, 함수 종료 시 저장했던 부모 행렬을 복원한다.
- 따라서 노드 월드 행렬은 `parent_world × node_local`이며 현재 `gx_scene.SceneResolver.world_matrix()` 구현과 일치한다.
- GX 파일에 저장된 행렬을 모두 월드 행렬로 간주하거나 부모 변환을 제거하는 방식은 클라이언트 동작과 다르다.

## `arm32_sppoo.gx` 판정

- 노드 10개, 메시 5개이며 `merge_head → merge_a/merge_b` 두 가지 가지 아래에 부품이 배치된다.
- `merge_b`에는 X축 `-0.6` 이동이 실제로 저장되어 있다. 오른쪽 가지의 추가 이동은 파서 오류가 아니라 원본 노드 변환이다.
- 변환 적용/미적용 렌더에서 부품 배치가 유지된 이유는 Blender 노드 계층이 GX의 재귀 합성을 이미 재현하기 때문이다.
- 텍스처와 UV는 정상이며, 보이는 벌어진 구성은 텍스처 결함으로 분류하면 안 된다.

## 전체 코퍼스 검증

- 설치 데이터의 고유 GX 780개에서 파서 부모와 `SceneResolver`의 유효 부모를 비교했다.
- 이름/대칭 복구 규칙으로 변경된 부모는 0개였다. 현재 데이터에서는 파일의 실제 마커 계층을 그대로 사용한다.
- 텍스처 회귀 테스트와 Python 문법 검사를 통과했다.

## v2.0 도구 반영

- Native 뷰어 보고서 탭에 모든 노드의 전체 부모 경로를 표시한다.
- 각 노드에 프레임별 `local translation → world translation` 값을 함께 표시한다.
- 타임라인 이동 시 보고서도 갱신되므로 행렬 애니메이션에 따른 계층 위치 변화를 수치로 검사할 수 있다.
