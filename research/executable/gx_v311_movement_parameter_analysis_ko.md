# Nova1492 GX 분석 v3.11 — missileparam 소비자 분류

## 레코드 배치

`missileparam`의 최대 세 값은 공격 변형 레코드에 다음처럼 저장된다.

| 설정 인덱스 | 레코드 오프셋 |
|---:|---:|
| `[0]` | `+0x3C` |
| `[1]` | `+0x40` |
| `[2]` | `+0x44` |

이 필드는 하나의 공통 의미를 갖는 벡터가 아니다. 이동 타입과 후처리 경로에 따라 서로 다른 의미로 재사용된다.

## 프레임별 위치 계산 소비자

| 이동 타입 | 소비 필드 | 코드 | 의미 |
|---:|---:|---:|---|
| 0 직선/집중선 | 없음 | `0x00440F42` | 시작점과 목표점 및 `t²`만 사용 |
| 1 표면 | 없음 | `0x00440F01` | 시작점/목표점 보간 |
| 2 포물선 | `+0x3C` | `0x00440F7B` | 거리와 함께 수직 포물선 높이 계산 |
| 6 내부 타입 | `+0x3C` | `0x004410B0` | 변환된 위치의 Y에 직접 더함 |
| 7 베지어 | 없음 | `0x00440DAC` | 초기화 때 저장한 P1/P2만 사용 |
| 8 각 | `+0x3C` | `0x00441548~0x00441565` | 각 궤도의 수직 곡률 계수 |

타입 3~5의 점프 테이블 엔트리는 공통 종료 지점으로 연결되어 실제 위치 공식이 없다. 현재 설정 로더도 이 타입 이름을 만들지 않는다.

## `+0x44` 소비

세 번째 값은 두 곳에서 확인된다.

1. 베지어 초기화 `0x0043F45C`, `0x0043F667`
   - `0`: 설치본이 사용하는 난수 수직평면 제어점 생성
   - `1`: 별도 호환 제어점 생성 후 P2=P1
   - 그 밖의 값: 두 생성 경로를 모두 건너뜀
2. 속도 클래스 1의 방향 행렬 갱신 `0x004416F9~0x0044179E`
   - 진행률과 곱해 회전 행렬에 전달되는 각도를 만든다.

따라서 `+0x44`를 단순히 베지어 모드 값으로만 취급하면 다른 이동 타입의 방향 애니메이션을 놓치게 된다.

## `+0x40`

분석한 미사일 생성·위치 갱신·방향 갱신 범위에서는 공격 레코드 `+0x40`을 직접 읽는 명령이 확인되지 않았다. 공격 객체 자체의 `+0x40`은 별개의 1바이트 상태 필드이므로 혼동하면 안 된다.

설치본에서 두 번째 값이 흔히 `1.0`으로 존재하더라도 현재 클라이언트의 확인된 미사일 런타임에서는 예약/미사용 호환 필드로 분류하는 것이 타당하다.

## 2026 구현 지침

- 설정 포맷 호환을 위해 세 값은 모두 보존한다.
- 위치 공식에는 이동 타입별로 실제 소비되는 값만 적용한다.
- 베지어 타입 7에는 `[0]=0.7`, `[1]=1.0`을 임의 곡률 배율로 적용하지 않는다.
- `[2]`는 초기 제어점 모드와 방향 회전 경로를 분리해 구현한다.
