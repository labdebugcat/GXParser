# Nova1492 GX 분석 v3.12 — 베지어 비제로 호환 분기

## 분기값

베지어 초기화는 레코드 `+0x44`를 부동소수점으로 비교한다.

| 값 | 동작 |
|---:|---|
| `0.0` | 설치본용 P1/P2 난수 생성 |
| `1.0` | 레거시 단일 제어벡터 생성 |
| 그 외 | 제어점 생성부를 건너뜀 |

설치본의 베지어 6종은 모두 `0.0`이므로 `1.0` 분기는 미사용 호환 코드다.

## 각도 헬퍼

`0x0046C7E0`은 입력 2D 벡터 `(x,y)`에 대해 길이와 0~360도 각도를 계산한다.

```text
length = sqrt(x*x + y*y)
angle = acos(x/length) * 180/pi
if y < 0: angle += 360
```

이 각도는 이후 sine/cosine 계산에 들어가지만, 동시에 고정각 `π/2`를 사용한다. x/y 성분에는 `cos(π/2)`가 곱해지고 z 성분에는 `sin(π/2)`가 곱해지므로 수학적으로 전개하면 각도 의존 성분은 0으로 소거된다.

## 최종 식

```text
F = normalize(target-start)
D = length(target-start)
q = randomRange(0.1, 0.2)

C = F * (q*D)
P1 = C
P2 = C
```

로컬 벡터는 `(0,0,qD,0)`이다. 마지막 동차 성분이 `0`이므로 아핀 행렬의 origin 열은 더해지지 않는다. 즉 결과는 월드 위치에 start를 더한 점이 아니라 원점 기준 방향 벡터다.

저장 직후 `0x0043F835~0x0043F859`가 P1의 16바이트 전체를 P2로 복사한다. 따라서 이 모드의 3차 베지어는 두 제어점이 완전히 같다.

## 호환성 판단

이 결과는 일반적인 베지어 제어점 배치로는 부자연스럽지만, 코드상 동차성분 `w=0`과 P1→P2 복사는 명확하다. 사용 데이터가 없으므로 원본 동작을 수정해 해석하지 않고 레거시 호환 모드로 그대로 보존해야 한다.

2026 구현에서는 다음 두 선택을 분리하는 것이 안전하다.

- 원본 호환: 위 식과 `w=0` 동작을 그대로 재현
- 현대 안전 모드: 콘텐츠 제작자가 명시적으로 요청할 때만 start 기준 위치로 보정
