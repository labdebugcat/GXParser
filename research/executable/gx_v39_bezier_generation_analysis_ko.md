# Nova1492 GX 분석 v3.9 — 베지어 제어점 생성 분기

## 결론

베지어 제어점 생성 루틴 `0x0043F292~0x0043F85D`는 공격 변형 레코드의 `+0x44`, 즉 `missileparam[2]`에 따라 분기한다. 설치본의 베지어 공격 6종은 모두 `missileparam = 0.7 1.0 0.0`이므로 실제 데이터에서 실행되는 것은 `+0x44 == 0` 경로뿐이다.

## 난수 함수

`0x00471060`은 CRT `rand()` 결과를 부동소수점 구간으로 옮긴다.

```text
randomRange(low, high) = low + rand() * (high-low) / 32767
```

어셈블리의 `fild`, `fsub`, `fmul`, `faddp` 순서와 `0x006DA858 = 1/32767`로 확인된다. 따라서 동일한 CRT 난수열을 공급하면 원본과 같은 범위 변환을 재현할 수 있다.

## 설치본에서 사용하는 제로 분기

시작점과 목표점의 차이로 정규 직교 프레임을 만든 뒤, 두 번의 각도 난수와 두 번의 크기 난수를 사용한다. 공격 객체 `+0x38`에 저장된 시작점-목표점 거리 `D`를 기준으로 범위는 다음과 같다.

| 제어점 | 각도 난수 | 거리 난수 |
|---|---:|---:|
| P1 | `0° .. 90°` | `0.1D .. 0.3D` |
| P2 | `-90° .. 0°` | `1.4D .. 1.6D` |

각도는 `π/180`을 곱해 radians로 바꾼 뒤 삼각함수 헬퍼 `0x0059C793`에 전달된다. 생성된 로컬 오프셋은 앞서 만든 방향 프레임으로 변환되고 기준 위치에 더해진다.

- P1 저장: `0x0043F53F~0x0043F570`, `controlBuffer+i*32`
- P2 저장: `0x0043F636~0x0043F65E`, `controlBuffer+i*32+0x10`

P1과 P2에는 각각 별도의 각도/거리 난수 호출이 있으므로 미사일마다 총 네 번의 `randomRange` 호출이 소비된다. 정확한 결정론적 재현에는 전역 CRT `rand()` 상태와 다른 게임 시스템이 먼저 소비한 호출 수까지 같아야 한다.

## 비제로 분기

`missileparam[2]`가 0이 아니면 `0x0043F667` 이후의 별도 경로로 진입한다. 이 경로는 방향 벡터를 다시 정규화하고 2차원 각도 변환을 거쳐 P1을 만든 다음 P2에 P1을 복사한다(`0x0043F835~0x0043F859`). 그러나 설치본 6개 베지어 정의에는 이 경로를 요청하는 데이터가 없다. 따라서 이는 엔진이 지원하지만 현재 콘텐츠에서는 사용하지 않는 호환 분기로 분류한다.

## 설치본 베지어 정의

`AP102`, `AP103`, `AP122`, `AP201`, `AP205`, `AP206` 모두 동일하게 `missileparam[2] = 0`이다. 미사일 수는 2 또는 4이며 각 미사일이 독립적으로 네 번의 난수를 소비해 서로 다른 곡선을 만든다.

## 구현 경계

현재 단계에서 설치본이 사용하는 분기, 난수 범위, 호출 횟수, 제어점 저장 위치는 확정됐다. 좌표 프레임의 축 부호 및 `missileparam[0:2]`가 로컬 성분에 적용되는 정확한 식은 다음 단계에서 SIMD/벡터 헬퍼의 인자 순서까지 펼쳐 고정한다.
